# UI_DIRECTIONS — 三套设计方向

> 本文档描述围绕**真实产品**的三套高保真 UI 重设计。产品真实形态是：
> **本地运行的多 Outlook 账号 OAuth 凭证管理 + 邮件读取 + 验证码提取工具**。
> 三套 Demo 共享同一份虚构 Mock 数据（`ui-demos/shared/mock-data.js`），核心能力一致，视觉语言与交互重点明显不同，以便公平比较。
>
> 数据安全：所有邮箱、client_id、token、邮件正文均为「结构真实但完全虚构」，不连接任何真实邮件服务，不使用任何真实凭证。

---

## 共享的数据模型与真实功能基线

| 能力 | 说明（对齐 server.js / public/app.js 的真实实现） |
|---|---|
| 账号舰队 | 10 个虚构 Outlook/Hotmail 账号，各有健康状态：可用 / 检测中 / 失活 / 异常 |
| 导入凭证 | 粘贴 `email----client_id----refresh_token`（或 CSV），写入本地 SQLite |
| 健康检测 | 失活判定：仅 `invalid_grant`、账号禁用（AADSTS50057）、不存在（AADSTS50034）等**终态**失败算失活；超时/限流等可重试错误不算 |
| 批量清理 | 检测失活 → 二次确认 → 批量删除（真实产品此操作不可撤销，Demo 补了撤销） |
| 读取邮件 | 每账号读取最近邮件（真实产品固定最近 3 封） |
| 验证码提取 | 从邮件抓取数字码 / 字母数字码 / 验证链接，带置信度，一键复制 |
| Token 保活 | 每 6 小时刷新 refresh token，返回新 token 时轮换写回 |
| 网站标记 | 用户自定义网站（GitHub / Amazon…），在账号旁显示 |

三套方案唯一不同的是「如何组织和呈现这些能力」。**没有通用邮箱的撰写/回复/会话**——因为真实产品是只读的凭证/验证码工具，强行加入会重复第一版「做成另一个产品」的错误。

## Demo A — 操作调度台（Ops Console）

- **路由**：`/ui-demos/efficient/`
- **目标用户**：管理几十上百个 Outlook 账号、频繁取验证码的重度用户 / 运维（**当前产品的真实用户画像**）
- **设计理念**：把界面当监控大盘。像 SRE 看仪表盘一样一屏掌握整个账号舰队的健康与验证码。

**视觉语言**
- 深色任务控制台，细网格背景，`JetBrains Mono` 等宽字体承载所有数字（未读、置信度、时间、client_id）。
- 单一强调色（电蓝 `#4d8dff`）+ 语义色（绿=可用 / 黄=检测 / 红=失活）。克制、专业、零多余装饰。

**布局与交互**
- 三栏：舰队统计+筛选 侧栏 ｜ 账号舰队表（紧凑单行，一屏 10+）｜ 账号详情（验证码卡 + 最近邮件 + 失活修复）。
- 命令栏即时过滤；键盘流 `j/k` 移动、`x` 勾选、`f` 读取、`c` 复制邮箱、`/` 过滤、`1–5` 切筛选、`?` 帮助。
- 批量：行内 checkbox + 批量条；「检测失活」一键选中所有失活账号；删除走**确认弹窗（列出邮箱）+ 5 秒撤销**。
- Refresh Token 保活面板（上次运行、成功率、轮换、失败）常驻侧栏。

**对应审查问题**：P1-12（信息密度）、P1-5（删除防护+撤销）、P1-7（批量/键盘并行）、P2-14（深色）、P2-15（键盘）。

## Demo B — 清爽看板（Calm Dashboard）

- **路由**：`/ui-demos/calm/`
- **目标用户**：账号不多、偶尔来取个验证码的轻量用户
- **设计理念**：把「管理一堆账号」这件本来焦虑的事，变成一眼看懂、一点即用。

**视觉语言**
- 浅色、柔和渐变、大圆角（20px）、大留白、`Plus Jakarta Sans`。温和、现代、零压力。
- 靛蓝主色 `#4f6bff`；验证码用大号等宽绿字，成为视觉焦点。

**布局与交互**
- 单列居中（940px）：一句话健康摘要（"你的 10 个账号里，6 个状态良好"）+ 健康度条形图 + 验证码磁贴网格 + 失活提醒条 + 账号卡片。
- **验证码磁贴**：把跨账号的最新验证码提到最显眼处，一键复制/打开——直击这个工具最高频的动作。
- **失活提醒条**：红色卡片列出需重新登录的账号，「检测并清理」一步到位（带确认 + 撤销）。
- 账号卡片：状态药丸、网站标记圆点、未读数、"有验证码"标记；点击进入全屏阅读页看邮件与验证码。

**对应审查问题**：P1-12、P2-10（引导/空状态）、P2-13（对比度/克制）、P2-16（移动端天然友好）、P3-19（安全说明）。

## Demo C — AI 指挥中心（AI Command Center）

- **路由**：`/ui-demos/ai-native/`
- **目标用户**：想让工具更聪明、愿意让 AI 帮忙分流的用户；探索区别于「纯手动凭证工具」的方向
- **设计理念**：AI 负责理解整个舰队、分流、给出下一步建议；人负责决策。**AI 绝不自动删除账号、绝不代取验证码**。

**视觉语言**
- 深色玻璃拟态 + 紫（`#9d7bff`）青（`#46e0d8`）辉光渐变，`Sora` 字体。科技感强，明确传达「AI 原生」的差异化定位。

**布局与交互**
- **AI 舰队摘要**：进入即读一段自然语言概况——"10 个账号中 6 个正常，2 个凭证失效需处理，已提取 9 个验证码，建议先清理失活再取验证码"，配 4 个统计。
- **自然语言操作**："找出所有失活的账号""还有哪些验证码没取"→ AI 回显对指令的理解并筛选。
- **三条智能分流泳道**：待取验证码（直接显示码）/ 需要处理的失活账号 / 高未读账号，每条带 AI 摘要 + 建议动作。
- **账号抽屉**：AI 洞察（这个账号什么情况）+ **判断依据**（为什么判为失活/验证码：命中 invalid_grant 终态、命中验证码格式与关键词）+ AI 建议的下一步（重新导入 / 复制验证码 / 读取），每个都要用户点击确认。
- 底部常驻控制声明："🔒 AI 只做分析与建议——删除账号、复制验证码、读取邮件都由你点击触发。"

**对应审查问题**：P2-9（把原始 AADSTS/IMAP 报文翻译成人话）、P2-11（失活账号就地修复引导）、并探索差异化方向。

## 三套方案速览

| 维度 | A 操作调度台 | B 清爽看板 | C AI 指挥中心 |
|---|---|---|---|
| 视觉基调 | 深色 · 任务控制台 | 浅色 · 柔和大留白 | 深色 · 玻璃紫青 |
| 信息密度 | 高 | 低 | 中 |
| 字体 | Inter + JetBrains Mono | Plus Jakarta Sans | Sora |
| 主色 | 电蓝 #4d8dff | 靛蓝 #4f6bff | 紫青 #9d7bff→#46e0d8 |
| 交互重点 | 键盘 + 批量 + 表格 | 摘要 + 磁贴 + 卡片 | AI 摘要 + 自然语言 + 分流 |
| 最适合 | 大量账号的重度/运维用户 | 少量账号的轻量用户 | 想要 AI 辅助的用户 |
